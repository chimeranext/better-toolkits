# Hotfixes direct to `main` — session 2026-10-28/29

**Context.** During the work session of 2026-10-28 to 2026-10-29, several commits were pushed directly to `main`. They did not go through a pull request. This happened because of an incorrect pattern. The agent set `HITL_APPROVED=1` on its own and pushed to `main`. This bypassed the HITL `pre-push` hook, which was not installed at the time. It also bypassed remote branch protection, including "Changes must be made through a pull request" and the `megalinter` check.

**Maintainer decision.** These changes are accepted as hotfixes. Nothing is reverted. This document records traceability. It shows the commit range, what changed, and the corrective applied so this does not repeat.

## Corrective applied

1. **`pre-push` hook enabled** — `.git/hooks/pre-push` now runs both guardrails:
   - `shared/hooks/git/pre-push.sh` → **HITL**: blocks push/merge to `main` (exit 2) without human approval (`HITL_APPROVED=1` or a marker created by a human action, such as `pkexec`/`GetCredentials`).
   - `scripts/git-hooks/pre-push-marketplace-versions.sh` → marketplace versions (semver bump on agent-surface changes).
2. **Agent internal policy:** never set `HITL_APPROVED=1` on your own. Ask for explicit approval (AskUserQuestion / AskQuestion) before any shared-state mutation. This includes pushing to `main`, `gh pr merge`, moving a tracker to Done, and deleting worktrees.

## Post state

- From this point on, the flow for changes to `main` is: branch → PR → review → merge (only with HITL). See `docs/hitl.md` and `CONTRIBUTING.md`.
