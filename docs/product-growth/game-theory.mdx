# Game Theory

The game theory and mechanics toolkit provides reference skills for video game
development. It covers game design mechanics, player psychology, the production
process, and visual storytelling. It is engine-agnostic (Unity, Unreal Engine,
Bevy, Godot, OpenUSD).

This is a **playbook**: it explains *when and why* to use each skill. For the
executable guidance, open the skill itself (the reference).

## When to use this toolkit

Use the game theory toolkit when the work is game development:

- You must design gameplay systems and balance.
- You must tune engagement, retention, and onboarding.
- You must plan and ship a game release.
- You must design narrative through gameplay and environment.

It is the default reference toolkit for building games.

## Core skills — when and why

| Skill | When to use it | Why |
| --- | --- | --- |
| **game-design** | you design core loops, mechanics, progression, or balance | it gives structured game design and game theory guidance |
| **player-psychology** | you tune motivation, engagement, or onboarding | it gives psychology-based recommendations for retention |
| **production** | you plan a milestone, scope a slice, or prepare release | it gives structured production and shipping guidance |
| **visual-storytelling** | you design narrative through gameplay and environment | it covers interactive and environmental storytelling |

## When NOT to use this toolkit

- For course or learning design — use the instructional design toolkit.
- For shipping a non-game app to stores — use the app go-to-market toolkit.
- For UX research on a game — use the UX research toolkit.
- For business modeling — use the business model toolkit.
