# Instructional Design

The instructional design toolkit guides course creators through complete course
design using CONTEXT → CONCEPT → BUILD → SHIP → REFLECT, Builder's Bloom's
Taxonomy, Ship-First Design, and Kirkpatrick evaluation. It produces standards
compliant (xAPI + cmi5) content from the start.

This is a **playbook**: it explains *when and why* to use each skill. For the
executable steps, open the skill itself (the runbook).

## When to use this toolkit

Use the instructional design toolkit when the work is learning design:

- You must design a complete course or module.
- You must author lessons, quizzes, challenges, and video scripts.
- You must create paths with credentials, or 1-on-1 session plans.
- You must evaluate whether learning actually works.

It is the default toolkit for building structured, measurable learning content.

## Core skills — when and why

| Skill | When to use it | Why |
| --- | --- | --- |
| **new-course** | you must design a full course | it runs the complete guided course design dialogue |
| **new-path** | you must group courses into a credential path | it builds an ordered path with an OpenBadge credential |
| **course-audit** | you must check a course against the framework | it audits structure, progression, and standards compliance |
| **course-visualize** | you must see the course design | it renders an interactive view of the course curve |
| **course-revise** | you must update a course | it classifies the change, bumps the version, and keeps IDs stable |
| **course-retro** | you must review a completed cohort | it produces a Kirkpatrick L1-L4 retrospective with priorities |
| **course-diff** | you must compare course versions | it reports what changed and the impact on enrolled learners |
| **slides-preview** | you must render lesson slides | it renders Marp decks from the course definition |
| **slides-generate** | you must create a slide system | it defines slide types, accents, and typography rules |
| **workbook-generate** | you need an interactive explainer | it turns text classes into an accessible HTML workbook |
| **teaching-context** | you must define the target learner | it builds the student persona and AI positioning |
| **research-methodology** | you must research a topic deeply | it sets source quality standards and artifact formats |
| **deep-research** | you need structured course chapters | it combines web and internal sources into chapters |
| **piber-narrative-architect** | you must build a persuasive argument | it structures problem, insight, big idea, execution, results |
| **blooms-taxonomy** | you must plan learning objectives | it scaffolds cognitive progression through a course |
| **ship-first-design** | you must align assessments to milestones | it uses backward design for builders |
| **learning-evaluation** | you must measure learning outcomes | it guides surveys, metrics, and retention analysis |
| **session-planner-1on1** | you must design a 1-on-1 session | it auto-detects coaching, mentoring, or tutoring |
| **coaching-session** | the session is coaching | it builds a performance-focused, time-bound plan |
| **mentoring-session** | the session is mentoring | it builds a long-term, integral development plan |
| **tutoring-session** | the session is tutoring | it builds a specific-topic plan with a concrete criterion |
| **session-plan-audit** | you must review a session plan | it checks against the coach/mentor/tutor framework |

## When NOT to use this toolkit

- For building the business model — use the business model toolkit.
- For shipping a course app to stores — use the app go-to-market toolkit.
- For UX research maps and interviews — use the UX research toolkit.
- A single quick question does not need the full authoring flow.
