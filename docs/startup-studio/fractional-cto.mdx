# Fractional CTO

The engagement and delivery toolkit for freelance and fractional CTOs. Use it
when you work for clients as an external technical leader and need to run a
complete engagement:

```
1. Pre-engagement  → /contract-nda           (NDA before sharing info)
2. Assessment       → /takeover-assessment    (risk evaluation)
3. Takeover         → /project-takeover       (4 SOP documents)
4. Project work     → /contract-psa           (project-specific agreement)
5. Ongoing          → /contract-retainer      (retainer or advisory + equity)
```

Beyond takeovers, the toolkit turns any client operational process into a
versioned, optionally-executable SOP, and formalizes product requirements before
code is written.

This is a **playbook**: it explains *when and why* to use each skill. For the
executable steps, open the skill itself (the runbook).

## When to use this toolkit

Use Fractional CTO when the work is a client engagement or a delivery process:

- You need to protect information before sharing project details.
- You are evaluating the risk of taking over an existing project.
- You are executing a project takeover.
- You need to formalize a project or a retainer relationship.
- You need to standardize a client's operational processes.
- You need to write product requirements before any code.

## Core skills — when and why

### Engagement lifecycle

| Skill | When to use it | Why |
| --- | --- | --- |
| **contract-nda** | before you share any project detail | it generates a bilingual NDA to protect information |
| **takeover-assessment** | before you commit to a project | it evaluates risk and produces an assessment wizard and contract |
| **project-takeover** | you are executing the transfer | it produces the 4 SOP documents: technical, client guide, request, ultimatum |
| **contract-psa** | you formalize a project | it creates a project-specific agreement with a shared risk model |
| **contract-retainer** | you start an ongoing relationship | it creates a retainer or advisory + equity contract |

### Process-engineering pipeline

| Skill | When to use it | Why |
| --- | --- | --- |
| **process-standardization** | a client's process is undocumented | it inventories processes and captures the current state |
| **automation-triage** | you must decide how a process runs | it issues a per-step verdict: human, RPA, AI agent, or hybrid |
| **sop-authoring** | you must write an operational procedure | it produces a structured SOP, plus an executable form when automatable |
| **playbook-authoring** | you need judgment under uncertainty | it writes a when/why playbook with a decision tree and options |
| **runbook-authoring** | you need an execute-under-pressure procedure | it writes a trigger-driven runbook with paired diagnose/repair scripts |
| **document-it / document-this** | you are unsure which document to write | it routes to SOP, playbook, or runbook authoring |
| **business-brain-setup** | a client needs a knowledge vault | it bootstraps a git/Obsidian business brain |

### Requirements-first pipeline

| Skill | When to use it | Why |
| --- | --- | --- |
| **requirements-authoring** | before any code is written | it writes a versioned PRD/SRS per ISO/IEEE 830 and ISO/IEC/IEEE 29148:2018, and derives OpenSpec and Linear issues |
| **clean-code-standards-setup** / **audit** | a client repo needs engineering standards | it bootstraps or measures adoption of DSMS, IFS, CPS, PRDS, BrS, QT4L, OST |
| **pentest-playbook-setup** | you run an authorized security engagement | it authors a stack-tailored security playbook, gated on written authorization |
| **oauth2-setup** | you need to gate a private site | it sets up an OAuth identity-aware proxy in front of private sites |

## When NOT to use this toolkit

- For legal or tax advice — contracts are templates that require lawyer review.
- For the single-founder journey from zero to funding — use the Startup Lifecycle toolkit.
- For portfolio-level decisions across multiple ventures — use the Venture Studio toolkit.
- For a freelancer staying as a single-member LLC — use the Digital Nomad toolkit.
