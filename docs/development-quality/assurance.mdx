# Assurance

The release-assurance evidence toolkit. Use it when you must prove a product is
safe to ship. It covers four pillars: testing, liveness, security, and
governance.

This is a **playbook**: it explains *when and why* to use each skill. For the
executable steps, open the skill itself (the runbook).

## When to use this toolkit

Use Assurance when the work is release readiness and evidence:

- You must verify a change actually works before release.
- You must prove the system stays alive in production.
- You must confirm the product is secure.
- You need metrics, gates, and receipts to prove you can ship.

It pairs with a disciplined dev lifecycle. Assurance writes evidence. The dev
workflow consumes that evidence in gates.

| Skill | When to use it | Why |
| --- | --- | --- |

| **flutter-accessibility** | you check a11y conformance | it covers Semantics, TalkBack/VoiceOver, and WCAG |

| **flutter-security** | you must harden a Flutter app | it covers pinning, secure storage, and obfuscation |

| **sre-security-compliance-automation** | you must enforce policy | it uses OPA and CIS benchmarks as code |
| **sre-container-security** | you must secure container images | it scans and signs images and watches runtime |

| **static-analysis** | you want fast, static defect detection | it runs multi-language linters automatically |

## When NOT to use this toolkit

- For writing a delivery process itself, use the Make No Mistakes toolkit.
- For business, growth, or strategy decisions, use the business toolkits.
- For a single quick question, do not start a full evidence flow.
