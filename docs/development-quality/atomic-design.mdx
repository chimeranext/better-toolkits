# Atomic Design

The Atomic Design toolkit. Use it to structure UI across a clear hierarchy:
atoms, molecules, organisms, templates, and pages. It works for Flutter and
Vite projects.

This is a **playbook**: it explains *when and why* to use each skill. For the
executable steps, open the skill itself (the runbook).

## When to use this toolkit

Use Atomic Design when the work is UI structure and quality:

- You need to decompose a feature into reusable components.
- You want to compare your app against a design system.
- You must audit component health and bundle quality.
- You want a consistent, maintainable component hierarchy.

It suits teams that build and maintain component-based interfaces.

## Core skills — when and why

| Skill | When to use it | Why |
| --- | --- | --- |
| **design-system-analyzer** | you compare your project against a design system catalog | it reports missing, partial, and extra components |
| **widget-decomposition** | a single component is too big or monolithic | it splits it into the Atomic Design hierarchy |

## When NOT to use this toolkit

- For generating a brand-new feature from scratch, use the generate command.
- For general framework questions, use that framework's own guidance.
- For a single styling tweak, you do not need a full decomposition.
